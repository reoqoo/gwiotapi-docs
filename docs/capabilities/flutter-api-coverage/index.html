已完成纵切面

Section titled “已完成纵切面”
  • 初始化：GWIoT.initialize、GWIoT.sdkInitFinish、GWIoT.dispose 已完成， flutter analyze、flutter test（初始化 7 例 + 冒烟 1 例）、flutter build apk --debug、 flutter build ios --debug --no-codesign 均通过（2026-09-14）。
  • 宿主服务：GWIoT.registerHostServices、GWIoT.clearHostServices 与五类宿主服务契约已完成， 验证同上（宿主服务 9 例）。
  • 账号与注册：验证同上（账号 12 例）。观察者通道由订阅引用计数驱动，GwiotLiveEvent 不重放旧事件。
  • 设备与物模型：验证同上（设备 12 例）。设备引用只传 deviceId，由原生在 SDK 上下文中解析。
  • 绑定/分享/升级：验证同上（生命周期 12 例）。产品与设备按标识在原生 SDK 上下文解析。
  • 两端 SDK 差异：安卓固定的 AAR（com.gwell:gwiotapi）没有 openBind(qrCodeValue, qrCodeFrom) 重载，跨端契约 只暴露两端共有的 openBind(qrCodeValue)。
  • 设备原生页面：验证同上（原生页面 7 例）。iOS 页面宿主检查返回插件错误码 25100（无 rootViewController）与 25101（root 未嵌入 UINavigationController）。
  • 相册/云/流量/帮助/反馈：验证同上（服务页面 10 例）。会员状态经观察者通道以 LiveData 发布。
  • 消息/二维码/推送/页面生命周期：验证同上（通知与生命周期 13 例）。扫码识别与页面生命周期以 LiveEvent 消费，不重放旧事件；推送注册仍由宿主 App 负责。
  • 播放器与对讲：验证同上（播放器 8 例，含 2 例平台视图 widget 测试）。播放器按 handleId 隔离，状态经观察者通道以 LiveData 发布；widget 移除默认释放，keepAliveOnDispose 显式保活。
  • 系统配置、日志与帮助页配置：验证同上（系统配置 9 例）。setLanguage/setEnvironment/setUiConfiguration 为同步透传，getPlatformConfig 为 suspend 桥接；SDK 日志经宿主日志服务单向转发。
  • 实际依赖版本以源码为准：Android 见 android/build.gradle，iOS 见 ios/gwiot_flutter_plugin.podspec（最低 iOS 15）。
  • 消息中心与扫码能力依赖原生 GWIoT SDK 注册的组件（IMessageCenterPageComponent / IQRCodeComponent）； 组件未注册时 SDK 返回 not found component 业务失败，插件原样透传而不在 Flutter 侧兜底页面。
  • 通道调用与「错误 + 数据」结果转换各自只有一个实现（lib/src/api/platform_call.dart、 lib/src/api/mapping.dart 的 _valueResultOf/_failureOf），门面与播放器控制器不再各维护一份； 测试数量 102 例（新增 2 例覆盖门面/播放器的通道异常收敛）。
  • Pigeon 生成器由 22.7.4 升至 26.3.4（pubspec.yaml 约束 ^26.3.4），三端生成文件已重新生成。 已核对 Kotlin 83 个接口方法、Swift 100 个 protocol 方法与 Dart 80 个公开类集合与升级前完全一致， 无签名破坏；新增能力为数据类 ==/hashCode（Dart 126 处）、Kotlin FlutterError 改继承 RuntimeException、生成期文件写入大幅减少。生成文件体积增量：Dart +5%、Kotlin +40%、Swift +28%。
  • 播放器画面与对讲需要真机验证：本仓库只保证两端平台视图注册、创建参数映射、控制通道与状态流编译/单测通过， 实际视频渲染、唤醒设备与音频链路依赖 SDK 运行时与真实设备。
  • 多路同屏只透传 SDK 原生页面（openMultiLivePage），Flutter 侧不实现网格 UI。
  • ILogOutputComponent 只能通过 GWPlugin.register 注册且 SDK 没有注销入口，因此原生在首次登记日志服务时注册一次； 之后 clearHostServices 只停止向 Flutter 转发，不会从 SDK 注销组件。
  • LanguageCode 枚举按 KMP 取值重新对齐（22 个取值，修正了此前 ar(12) 与 KMP 不一致的建模）； Theme.Fonts、图标对象与数据库内部字段不进入跨端契约。
  • 未知类型的一次性事件（accountEvent / deviceEvents / propsChanged / bindEvents）在观察流解码前被 过滤丢弃，不会伪造成「被踢出」「设备被删除」「离线」等具体事件；这是 code-review 修复的行为契约。
  • closeScanQRCodeScene 是本插件新增的补充 API：KMP IQRCodeComponent 的 openScanQRCodePage 通过 RecognizedCallback 交出 SceneCloseable，跨端无法把函数回调直接变成 Pigeon 参数，因此拆成 一次性事件 + 显式关闭方法（原始 SDK 调用签名不变）。
  • 安卓（Reoqoo 插件包）的扫码组件在跳转 reoqoo://config_net/scan_qrcode 之后会立即返回 Failure("not support return the qrcodeType")：它表示「页面已打开，但当前平台不把二维码类型回调给 调用方」，不是打开失败。宿主不要据此判断页面没起来（demo 已单独识别这条文案，不再记成失败）。 iOS 走 GWIoTKit，行为以真机为准。
  • 06 的「页面交接契约」验证止于两端编译 + 页面宿主检查（iOS 宿主不可用返回 25100 / 25101）， 没有真机集成用例。2026-09-17 补充：demo 阶段发现 Flutter 模板的根控制器是裸 FlutterViewController，SDK 页面因此无处可 push；已在 demo 侧包装导航控制器，并把这种情况 单独映射为 25101，宿主接入时能立刻定位。
  • 已知限制：设置服务的同步决策在缓存未命中时先返回 SDK 默认值再异步拉取 Dart 结果；Dart 侧宿主 实现抛出的意外异常映射为 Reason.Undefined（25000），Reason.NotFoundComponent（25001） 只用于未登记宿主服务的组件缺失场景。
