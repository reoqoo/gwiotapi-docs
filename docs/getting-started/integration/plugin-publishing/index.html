插件的发布与消费

本页说明版本如何确定、插件如何发布，以及宿主 App 如何消费。

本插件不做公开发布：只通过内网 GitLab（内部宿主 App）与 Gwell Nexus 的私有 Pub 源 （客户/合作方与内部）分发。

版本与标签约定

Section titled “版本与标签约定”

pubspec.yaml 的 version 与 Git 标签是同一个字符串，且标签不带 v 前缀：

标签是宿主 App 锁定版本的唯一依据，因此标签由人工在评审后创建——发布脚本绝不创建或推送标签。

插件版本跟随 com.gwell:gwiotapi 的前两段（Android 侧的原生依赖），第三段由插件自己维护： gwiotapi 1.8.0.6 → 插件 1.8.x；gwiotapi 升到 1.9 线时插件从 1.9.0 重新起算。iOS 的 GWIoTKit 约束是另一件事，跟随宿主实际可用的 iOS 原生版本，不参与插件版本号的计算

标签是宿主 App 锁定版本的唯一依据，因此标签由人工在评审后创建——发布脚本绝不创建或推送标签。

版本号跟随原生 GWIoTKit 的版本线（iOS 与 Android 都依赖它：iOS 是 CocoaPods trunk 上的 GWIoTKit，Android 是聚合包 com.gwell:gwiotkit）。两端版本线不一致时不单独升级：例如 iOS 已有 1.12 而 Android 还是 1.11 时，插件停留在 1.11，等两端都具备 1.12.0 再一起发 1.12。

CHANGELOG.md 遵循 Keep a Changelog：在 bump version 的同一个提交里 新增 ## <version> 段落，按行为描述变化。

宿主 App 消费插件的两种方式

Section titled “宿主 App 消费插件的两种方式”
方式 适用场景 版本锁定
Git 标签依赖 仅内部宿主 App（（内部主机已隐去） 只有内网可达） 精确 ref
Gwell 私有 Pub 源 客户、合作方与内部宿主 App 都可用（Nexus 主机外网可达，且当前匿名可读） 版本约束

取舍与理由简述：Git 标签只覆盖内网（GitLab 只有内网可达），好处是 零基础设施；面向客户/合作方统一走 Nexus 私有源，两条线共享同一份提交与标签。

Git 标签依赖

Section titled “Git 标签依赖”

⚠️ 这种方式只适用于内部宿主 App：（内部主机已隐去） 只有内网可达，客户/合作方解析不到该地址。

使用精确 ref，不要用分支。用分支会让每次 pub get 都不可复现。

Gwell 私有 Pub 源（客户与合作方可用）

Section titled “Gwell 私有 Pub 源（客户与合作方可用）”

hosted: 形式已经写明了源地址，消费者不需要再设 PUB_HOSTED_URL；只有想让所有包都走私有源时才需要 设那个环境变量。该仓库当前允许匿名读取：

该地址从外网可达，客户/合作方不需要任何凭据就能解析（实测匿名 pub get 通过；前提是反向代理已透传 请求协议，见下文「私有 Pub 源的状态与前置条件」）。
