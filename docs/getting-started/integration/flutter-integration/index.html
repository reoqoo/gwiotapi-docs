GWIoT Flutter Demo

宿主 App 接入 gwiot_flutter_plugin 的完整示例。插件把 GWIoT 的 iOS / Android SDK 封成一套 Flutter 接口，本工程演示怎么把它用起来：两种账号体系、设备列表与卡片、添加设备的四种方式、 设备事件、账号与设置页、消息推送。

示例覆盖两条账号路线，客户按自己已有的账号体系选一条照着写即可：

账号体系 谁来管账号 本工程如何演示
技威账号 技威云（SDK 内置账号服务） 手机号 / 邮箱注册登录、验证码、改密码
宿主账号 客户自己的后台 用 Supabase 模拟客户云，走云云对接换取登录票据

2. 依赖来源

Section titled “2. 依赖来源”

pubspec.yaml 已声明好依赖来源，直接 flutter pub get 即可：

插件没有发布到 pub.dev，只通过 Gwell 的私有 Pub 源分发（该源允许匿名读取，无需额外配置 PUB_HOSTED_URL）。地址不可达或未开通访问时，flutter pub get 会直接报 404 / 认证失败， 不会静默回落到别处——把错误发给我们即可。

4. 平台配置要点

Section titled “4. 平台配置要点”

Android

Section titled “Android”

依赖分两层，缺一层会出现「能初始化、SDK 却永远不就绪」：

  1. 插件自己只声明 com.gwell:gwiotapi（运行时 AAR），它的 POM 不含任何依赖。
  2. 宿主必须自己声明聚合包 com.gwell:gwiotkit:1.11.07，由它带入 plugin hub、Room/SQLite 等运行期依赖。

除此以外，工程里已经逐项写好的宿主配置（每一条都对应一个真实报错，别删）：

  • 全部 Maven 仓库：maven-gwiot、maven-releases、jitpack、jcenter 镜像、mvn.zztfly.com—— 少了会报 Could not find com.github.zhpanvip:viewpagerindicator 一类错误。
  • Kotlin 对齐 2.3.20 并用 compilerOptions.jvmTarget（2.3 已移除 kotlinOptions.jvmTarget(String)）。
  • Hilt 2.57.1 + @HiltAndroidApp 的 Application；kapt 需要显式加 org.jetbrains.kotlin:kotlin-metadata-jvm:2.3.20。
  • buildFeatures { dataBinding = true; buildConfig = true }：不开 dataBinding，点设备页右上角 + 进 SDK 扫码页会闪退（NoClassDefFoundError: DataBinderMapperImpl）。
  • 清单占位符与 tools:replace、jniLibs.pickFirsts，分别对应清单合并失败与重复 .so 失败。
  • Application 的初始化顺序（见 android/app/src/main/kotlin/.../DemoApplication.kt）： AppEnv.init → StorageManager.init → GwKeyValueManager... → 插件包初始化 → FirebaseApp。 顺序不对会在登录成功的一瞬间崩溃，而不是启动即崩，只看启动冒烟会漏掉。
  • Firebase 配置：工程自带的 android/app/google-services.json 是演示项目，正式集成必须换成 自己 Firebase 项目下发的同名文件（不要改名）。

iOS

Section titled “iOS”
  • 根控制器必须嵌进 UINavigationController：SDK 内置页面用当前导航栈 push，裸的 FlutterViewController 会让「接口调用成功但页面不出现」，而且 SDK 不报错。本工程用 GWIoTNavigationController 统一处理（系统导航栏的显示/隐藏按页面判断）。
  • 权限用途说明一项都不能少：访问受保护数据而没有对应的 NS*UsageDescription，iOS 会直接 终止进程而不是弹窗。工程已按 SDK 实际引用的隐私 API 补齐相机、相册读写、麦克风、定位、 蓝牙、局域网 + Bonjour、后台推送；新增用到隐私 API 的页面时先扫描 SDK 二进制确认键名。
  • Runner.entitlements 与 CODE_SIGN_ENTITLEMENTS 不要删：缺 aps-environment 时 registerForRemoteNotifications 会以 Code=3000 失败，现象是「权限给了但永远拿不到 APNs token」。
  • Firebase 配置：ios/Runner/GoogleService-Info.plist 同样是演示项目的，正式集成换自己的。

5. 两种账号体系怎么试

Section titled “5. 两种账号体系怎么试”

登录页左上角进开发者配置页，可以切登录模式、切 SDK 环境、看 SDK 状态与日志。 登录模式只在初始化时读一次，改完必须重启 App（页面上有重启入口）。

  • 技威账号：直接注册 / 登录，走技威云的账号服务。
  • 宿主账号：先用宿主账号（本工程用 Supabase Auth 模拟）登录，SDK 通过云云对接向客户云索取 登录票据。supabase/ 目录就是这套客户云的最小实现（两个 Edge Function + 建表迁移）， 客户照这个结构换成自己的后台即可。

登录后主界面有三个 tab：设备、事件、我的；设备页右上角 + 提供内置扫码、自定义扫码、 手动添加四种添加方式。右下角的悬浮按钮随时回到开发者配置页。

7. 常见问题

Section titled “7. 常见问题”
现象 多半是
initialize 返回成功，但 SDK 一直不就绪 Android 少声明 com.gwell:gwiotkit，或缺 SDK 传递依赖需要的 Maven 仓库
点设备的 + 进扫码页闪退（Android） 没开 buildFeatures.dataBinding
接口返回成功但 SDK 内置页面不出现（iOS） 根控制器没嵌 UINavigationController；插件会返回 25100 / 25101 提示是哪一种
一进相机 / 相册页就闪退（iOS） Info.plist 缺对应的 NS*UsageDescription
通知权限给了，却永远拿不到 token（iOS） 缺 aps-environment 授权（Code=3000），或跑在模拟器上
登录成功的一瞬间崩溃（Android） Application 里的初始化顺序没按第 4 节做
flutter pub get 报 404 / 认证失败 私有 Pub 源不可达或未开通访问
