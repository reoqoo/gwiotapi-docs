本地调试 gwiot_flutter_plugin

本页面向正在修改插件本身、并希望宿主 App 立即用上这些改动的人。

示例中的路径一律使用相对路径；除特别说明外，所有 shell 命令都假定当前工作目录是插件仓库根目录。

首选：在宿主 App 里用 pubspec_overrides.yaml

Section titled “首选：在宿主 App 里用 pubspec_overrides.yaml”

pubspec_overrides.yaml 可以在不改动受版本控制的 pubspec.yaml 的前提下覆盖依赖来源。 在宿主 App 的 pubspec.yaml 同级创建：

然后把它加入宿主 App 的 .gitignore，避免本地路径进入 CI 或队友的机器：

执行一次 flutter pub get。path 依赖会被软链进 .dart_tool/package_config.json，因此 后续 Dart 改动立即生效，不需要每次改完都重新 pub get。

要停止使用本地副本，删除 pubspec_overrides.yaml 并重新执行 flutter pub get。

Section titled “降级方案：在 pubspec.yaml 写 path 依赖”

无法使用 overrides 文件时，直接把依赖指向插件目录：

这种方式很容易被误提交。path 依赖一旦提交，会让所有未在该相对位置检出插件的机器全部失败， CI 也会直接挂掉。仅限一次性验证使用，提交前必须还原。

哪些改动会立即生效

Section titled “哪些改动会立即生效”
你的改动 宿主 App 需要做什么
lib/ 下的 Dart 代码（含 lib/src/models、lib/src/api） 无需操作。path 依赖是软链，下次热重载或重新构建即生效。
pigeons/gwiot_api.dart 里的通道契约 需要重新生成并重建两端，见下节。
android/src/main/kotlin/ 下的 Android 代码 重新构建 App（flutter run 或 flutter build apk --debug）。
ios/Classes/ 下的 iOS 代码 重新构建 App（flutter run 或 flutter build ios --debug --no-codesign）。
ios/gwiot_flutter_plugin.podspec 在宿主 App的 ios/ 目录重新执行 pod install，再重建。
pubspec.yaml（依赖、SDK 约束） 在宿主 App 执行 flutter pub get。

重新生成 Pigeon 契约

Section titled “重新生成 Pigeon 契约”

pigeons/gwiot_api.dart 是通道契约的唯一来源。修改后执行：

生成文件纳入版本控制，必须与契约改动一起提交：

  • lib/src/messages.g.dart
  • android/src/main/kotlin/com/yoosee/gwiot_flutter_plugin/Messages.g.kt
  • ios/Classes/Messages.g.swift

macos/Classes/Messages.g.swift 不是生成目标，它是 flutter create 留下的模板桩， 不会随契约变化。细节见 docs/architecture.md。
