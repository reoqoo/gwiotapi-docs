Device binding and management

This page covers the device binding entry points and the device management interfaces of the GWIoT SDK.

Prerequisites

Section titled “Prerequisites”
  • SDK initialization is done, and initialize returns success.
  • The app is signed in, and devices belong to the signed-in account.

Use built-in pages or build your own

Section titled “Use built-in pages or build your own”

Two entry points bind a device: scan the device QR code, or enter from the product list. The SDK ships built-in screens for both, and the interfaces are IBindComponent and IQRCodeComponent.

You can open the built-in pages directly, or customize your own pages through the interfaces the SDK provides.

Beyond the scan and product list entry points, the binding flow itself is built into the SDK. That flow involves fairly complex protocols between the device and the cloud, and you cannot customize it at present.

Built-in scan page

Section titled “Built-in scan page”

The SDK ships a scan page that enters binding once it recognizes a device QR code. You can replace the page title and the prompt text.

Custom scan page and QR code recognition

Section titled “Custom scan page and QR code recognition”

Implement scanning yourself, pass the QR code content to the SDK for recognition, and enter the binding flow.

Built-in product list page

Section titled “Built-in product list page”

The SDK provides a product list page for the supported products, and users pick a product there to start binding.

Custom product list

Section titled “Custom product list”

Fetch the supported product list first, then design and build your own, filtering and sorting it as needed.

When the user picks a product, pass the product information object to the SDK to start binding.

The SDK still runs the remaining binding steps.

Device management interfaces

Section titled “Device management interfaces”

The device management interfaces are in IDevMangerComponent. It provides three kinds of query: product list, device list and device details. Each query returns the result and also updates the matching cached list.

Call Returns Also updates
queryProductList() The supported product list The product list cache
queryDeviceList() The device list of the current account The device list cache
queryDevice("deviceId") The details of one device The cache for that device

Examples for the three platforms

Section titled “Examples for the three platforms”

Swift

Section titled “Swift”

The Swift example covers only the built-in page entry points. For the method names that start binding from a product or from QR code content, see the API reference.

Kotlin

Section titled “Kotlin”

Dart

Section titled “Dart”

The built-in scan page returns the recognized type through the qrCodeRecognized event stream.

Acceptance

Section titled “Acceptance”
  • After binding, the new device appears in the device list.
  • The device is still in the list after you relaunch the app.
  • Product names in your custom product list match the SDK cache.
  • A scanned device QR code takes the user into the binding flow.
  • The list refreshes after a device is removed from the account.
