Customer account login

This page covers how the customer app exchanges a login ticket when it does not use Gwell’s account service, and how it handles account events.

Prerequisites

Section titled “Prerequisites”
  • SDK initialization is done.
  • The customer cloud has completed cloud-to-cloud integration with Gwell Cloud and can obtain UserC2CInfo. For the cloud interfaces, see Customer cloud-to-cloud integration.
  • The customer app already has its own login flow and can tell whether a user is signed in.

When this applies

Section titled “When this applies”

The customer app registers and signs in users with its own account system, so users do not sign in to a Gwell account again. The customer cloud obtains the account credentials from Gwell Cloud, and the SDK handles only authentication and the device features that follow.

Login flow

Section titled “Login flow”

The overall flow:

1. The app detects a signed-in account

Section titled “1. The app detects a signed-in account”

An account counts as signed in whether the user signs in again or the app reads cached login information on a cold start.

2. Sign in to the SDK

Section titled “2. Sign in to the SDK”

After the app signs its user in, call the SDK’s login(hostUserId: String) method. hostUserId is the unique identifier of the user the app has signed in. The SDK uses it only to decide locally whether it has cached the login information for that user, and never uploads it to Gwell Cloud. The app can transform it with its own algorithm before passing it in.

3. The SDK requests login credentials from the app

Section titled “3. The SDK requests login credentials from the app”

If the SDK has not cached the login information for the given user, it requests the login credentials from the app.

The app implements the related SDK interfaces to return the login credentials.

Multi-device and single-device login

Section titled “Multi-device and single-device login”

The SDK tells its login terminals apart through the uniqueId field of the thirdCustLogin cloud interface.

  • For multi-device login, the app should fill this field with a unique ID of the phone. It only needs to be unique in practice. Generate it once and cache it, so it is not regenerated on every app launch. You can use the SDK’s GWIoT.phoneUniqueId() method, which already caches it.
  • For single-device login, this field can be a fixed value. Passing the same value as the unionId is recommended.

Handle account events

Section titled “Handle account events”

The SDK reports account events to the app through accountEvent. The app can observe this event and handle each one as needed.
