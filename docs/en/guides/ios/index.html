iOS coding guide

Development language

Section titled “Development language”

Use Swift.

The KMP project exports an Objective-C xcframework that iOS consumes. Converting Kotlin to Objective-C loses some common language features — a Kotlin enum, for example, becomes an Objective-C class, which is awkward to use.

To solve this, the KMP project uses the SKIE plugin. It modifies the xcframework the Kotlin compiler generates to restore support for some of those language features, which makes the Swift interfaces KMP generates friendlier. It supports Swift only.

The SDK also embeds some Swift extensions and methods through SKIE, which makes the Swift interfaces KMP exports easier to use.

If you are adding this SDK to an existing Objective-C app, bridge to the GWIoT interfaces through Swift. For a brand-new app, use Swift directly.

KMP’s Swift output is still in early development. Once it stabilizes, direct Swift framework export will be considered; if you are interested, read more.

SDK docs and code completion

Section titled “SDK docs and code completion”

In the following cases, look the interface up directly in the API docs.

  1. Kdoc comments on Kotlin code appear in the generated Objective-C header, but bugs can drop or garble some of them.
  2. When Xcode has not fully indexed the project, code completion may not appear as you type, especially with several projects open at once.

Value enums

Section titled “Value enums”

Kotlin has no value enums; sealed class is the closest thing, but each value becomes an Objective-C class when exported to Objective-C. SKIE provides the onEnum(of:) method, which turns them into enum form for easier use. GWResult above is one example, but for GWResult it is better to use gwiot_swiftResult(:) as described above.

Observe

Section titled “Observe”

Some properties in the interfaces are observable types.

  • LiveData<T>: you can observe changes to its value. Observing fires immediately with the current value, and value also returns the current value.
  • LiveEvent<T>: SDK events are delivered through this type. Unlike LiveData, it does not deliver past values.

LiveData<T> and LiveEvent<T> are similar to CurrentValueSubject and PassthroughSubject in Swift Combine, respectively.
