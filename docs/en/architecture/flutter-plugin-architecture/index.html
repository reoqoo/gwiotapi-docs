GWIoT Flutter 插件架构

This page has no maintained English version yet. The Chinese version is shown instead. Use your browser's built-in translation to read it.

本文件记录已确认的插件实现边界。（本文件只记录已确认的实现边界。）

分层

Section titled “分层”

虽然 KMP GWIoT 在内部把能力委托给各组件，Flutter 的公共 API 仍只使用一个 GWIoT 门面。底层文件和 Pigeon API 可按职责划分，以降低实现复杂度；这种划分 不得泄露到 package 的公共导出面。

数据与错误

Section titled “数据与错误”
  • Pigeon 不表达 Kotlin 的泛型、接口继承和 sealed class；通道使用带 discriminator 的 平面消息类型，Dart 模型层将它们转换为 sealed/枚举/值对象。
  • 所有实体只复制 KMP 的公共可见字段；模型必须带序列化和对齐测试。
  • GWResult<T> 在 Dart 中为 GwiotResult<T>。调用者显式处理 success/failure； 传输、编解码或违反调用约束的错误才使用 GwiotException。
  • 「错误 + 数据」形状的 G*ResultMsg 统一由 mapping.dart 的 _valueResultOf / _failureOf 还原为 GwiotResult；通道调用统一由 platform_call.dart 的 gwiotCall / gwiotUnitCall / gwiotMapCall 包装，门面与播放器控制器不再各自维护 try/catch 与异常转换。
  • 门面与播放器控制器对 GwiotResult/GwiotException 的划分是同一套语义：SDK 业务失败是 GwiotResult.failure，通道异常与调用约束问题才是 GwiotException。

生命周期与事件

Section titled “生命周期与事件”
  • GwiotLiveData<T> 同时保留 value 和变化流；GwiotLiveEvent<T> 只表示事件流。
  • 原生观察者由 Dart 的订阅引用计数管理：第一位订阅者创建、最后一位退订者释放，插件 dispose 时一并清理。
  • Flutter 注册宿主服务必须发生在 GWIoT.initialize 之前。若未注册，保持 KMP 的默认 语义：账号服务失败、设置服务默认放行、支持服务回退 SDK 内建页面。
  • KMP 的宿主服务混用异步与同步调用：账号查询、云/流量/支持页面打开是异步接口，可以直接 经 Pigeon 往返；isCustomOpenCloudPage、isCustomOpenTrafficPage、isHiddenSupportEntry 以及设置服务的决策是同步接口，必须由注册消息缓存，设置服务的设备级决策在缓存未命中时先 返回 SDK 默认值再异步预热。原生到 Dart 的调用统一在主线程发起，避免阻塞 SDK 主线程。

播放器

Section titled “播放器”

GwiotPlayerView 是渲染容器，控制由 GwiotPlayerController 承担。Android 使用 AndroidView 承载 SDK FrameLayout，iOS 使用 UiKitView 承载 SDK 的 UIView 包装。 平台视图创建时按 handleId 调用 GWIoT.getLivePlayer，因此控制器在视图创建完成前调用控制方法会 得到「句柄不存在」的业务失败。widget dispose 默认释放播放器资源（keepAliveOnDispose: false）， 保活需显式选择并由调用方负责释放。

代码生成

Section titled “代码生成”

通道契约的唯一来源是 pigeons/gwiot_api.dart，三端生成文件均纳入版本控制：

  • 生成目标由 PigeonOptions 决定：lib/src/messages.g.dart、android/.../Messages.g.kt、 ios/Classes/Messages.g.swift。macos/Classes/Messages.g.swift 不在生成目标内，仍是 flutter create 模板留下的 GwiotHostApi.getPlatformVersion 桩，不受契约变更影响。
  • 生成器版本由 pubspec.yaml 的 pigeon 约束决定，当前为 ^26.3.4（Flutter 3.35 线可解析的 最高版本）。27.x 要求 Dart 3.10（Flutter 3.38）、28.x 起要求 Dart 3.11（Flutter 3.41）， 升级生成器必须同步抬高 environment.flutter / environment.sdk 并重跑三端验证。
  • 生成文件由工具全量重写，评审时只需关注接口签名而非逐行差异；本仓库的手写代码不引用生成文件里的 工具符号（wrapResult / wrapError / MessagesPigeonUtils 等），因此生成器升级不会波及手写实现。
  • pigeon 是 dev_dependency，不会传递给下游使用方，不影响使用者的 Flutter 版本下限。

当前恢复检查（2026-09-14）

Section titled “当前恢复检查（2026-09-14）”
  • pigeons/gwiot_api.dart 已声明大范围 Host/Flutter API，且生成的 Dart、Kotlin、Swift 消息文件存在。
  • lib/src/models/gwiot_models.dart 已有一批手写模型。
  • 顶层 GWIoT 门面已建立三个纵切面：初始化（initialize、sdkInitFinish、dispose）、 宿主服务（registerHostServices、clearHostServices、五类服务契约）与账号（登录/登出/资料/ 注册/验证码/推送 token，以及 isLogin、currentUser、accountEvents），并具备可被 fake 替换的 GwiotFlutterPluginPlatform 测试 seam。
  • 状态流与事件流经通用观察者通道（GwiotObserverApi + GwiotObserverEvents + Dart 侧 GwiotObserverHub/GwiotObservedStream）实现，按订阅引用计数建立与释放原生观察。
  • Android/iOS plugin 目前映射初始化、连通性、五类宿主服务与宿主日志输出、账号、设备/物模型、 设备生命周期（绑定/分享/升级）、设备原生页面、相册、云服务/会员、流量、帮助与问题反馈、 消息中心、二维码、系统推送、页面生命周期、播放器平台视图与控制面，以及语言/环境/UI/平台配置。 所有已实现的公开契约见 docs/api-coverage.md。
  • SDK 原生页面在 Android 使用插件持有的 Activity，在 iOS 由 GWIoTKit 通过当前导航栈展示； Flutter 侧只传设备引用与页面选项。iOS 在每个页面入口前检查页面宿主：拿不到 rootViewController 返回插件错误码 25100，root 链路上没有 UINavigationController 返回 25101，避免「调用成功但 页面不动」的静默失败。
  • 产品与设备在跨端契约里都只传标识（pid / deviceId）：原生适配层从 SDK 的设备列表与产品 列表缓存解析出真实对象，避免用字符串重建 SDK 枚举字段，也避免 Flutter 侧构造原生对象。
  • 相册、云/流量与帮助页面复用同一套设备引用解析：device 为空时把 null 传给 KMP，保留 SDK 的“无设备上下文”（首页相册、全局云服务）语义；非空引用解析失败则以业务失败返回。
  • 会员状态（ICloudServiceComponent.membershipInfo）与设备列表一样，经通用观察者通道以 LiveData 语义发布，membershipInfo 流按订阅引用计数建立/释放原生观察并在订阅时重放当前值。
  • 一次性通知走事件通道而不是状态通道：扫码识别（qrCodeRecognized）与页面生命周期 （pageLifecycle）都建模为 LiveEvent，订阅前发生的事件不会被重放；未读数 （unreadCount）是状态，订阅时重放当前值。
  • 扫码回调由 SDK 在识别到二维码时触发，原生把识别结果推给当前已订阅的观察者，并暂存 SDK 交出的 场景关闭动作；Dart 只能经 closeScanQRCodeScene 关闭该场景，无法伪造新的扫码场景。
  • 系统推送注册属于宿主 App：插件只接收宿主转交的原始 payload（Android 编码为 JSON，iOS 转为 userInfo 字典），不申请通知权限、不注册系统推送通道。
  • 系统配置走同步通道：setLanguage / setEnvironment / setUiConfiguration 直接透传（语言用 Dart 枚举名、环境用 Test/Beta/Prod），只有 getPlatformConfig 是 suspend 桥接；UI 配置的图标是 平台专有对象，不进入跨端契约。
  • SDK 日志通过宿主日志服务（ILogOutputComponent）单向转发到 Flutter。该组件先于 IHostService 体系且 SDK 没有注销入口，所以原生只在首次登记日志服务时用 GWPlugin.register 注册一次，之后 clearHostServices 仅停止向 Flutter 转发。
  • 播放器由平台视图持有：Dart 侧只分配 handleId 并把它作为创建参数传给平台视图，原生在视图创建时 调用 GWIoT.getLivePlayer 并把 SDK 视频容器挂到容器视图上；控制方法只按句柄操作已注册的播放器， 句柄不存在时返回业务失败。播放器状态经观察者通道的 playerState 目标按句柄隔离发布。
  • 设备相关公开 API 只接收 GwiotDeviceRef（deviceId）；原生适配层从 deviceList 缓存解析 IDevice 与方案，解析失败以业务失败结果返回，Flutter 侧不需要构造原生设备对象。

因此，生成的通道文件只代表“契约已起草”，不代表 API 已可用。实施须按纵切面继续：每个领域 同时补齐门面、两端映射、fake 平台测试与 API 覆盖表状态。

术语表

Section titled “术语表”
  • 门面（facade）：顶层的 GWIoT 类，Flutter 调用方访问 SDK 的唯一业务入口。
  • 纵切面（slice）：一个能力域从 Pigeon 契约、Dart 门面、fake 测试到两端原生映射的完整实现。
  • 平台 seam：GwiotFlutterPluginPlatform，门面访问原生的唯一接口；测试通过替换它脱离原生 SDK。
  • 宿主服务（host service）：由宿主 App 实现、SDK 反向调用的契约（账号、云、流量、设置、支持、日志）。
  • LiveData：既有当前值又可订阅的状态，跨端实现为 GwiotLiveData（replayLast: true）。
  • LiveEvent：只表示“发生过”的一次性事件，跨端实现为 GwiotLiveEvent（不重放）。
  • handleId：播放器的原生句柄标识，由 Dart 分配，原生用它定位已注册的 SDK 播放器。
  • 设备引用（device ref）：跨端只传 deviceId（与可选 solution），原生在 SDK 上下文中解析 IDevice。
