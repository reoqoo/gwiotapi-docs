iOS integration

中文说明

The plugin links the prebuilt static framework GWIoTKit (published on CocoaPods trunk). iOS 15 is the minimum. A few build settings cannot be supplied by the plugin’s podspec and must live in the host app’s Podfile.

1. Podfile requirements

Section titled “1. Podfile requirements”

Also set the host app’s iOS Deployment Target to 15.0 or higher in Xcode (Runner target → Build Settings → iOS Deployment Target). CocoaPods cannot raise the host app’s deployment target from a podspec.

2. What the plugin already handles

Section titled “2. What the plugin already handles”

ios/gwiot_flutter_plugin.podspec sets these for its own pod target, so you do not need to repeat them:

Setting Value Scope
DEFINES_MODULE YES plugin pod target
BUILD_LIBRARY_FOR_DISTRIBUTION YES plugin pod target
EXCLUDED_ARCHS[sdk=iphonesimulator*] arm64 i386 plugin pod target only

The host app target is covered by two other parties, which is why the plugin does not need to pass the setting through user_target_xcconfig:

  • GWIoTKit carries EXCLUDED_ARCHS[sdk=iphonesimulator*] = arm64 as both pod_target_xcconfig and user_target_xcconfig, so it reaches the host target (Pods-Runner.*.xcconfig).
  • Flutter’s tooling writes EXCLUDED_ARCHS[sdk=iphonesimulator*]=i386 arm64 into ios/Flutter/Generated.xcconfig for the host app.

The IPHONEOS_DEPLOYMENT_TARGET setting is not and cannot be covered by any podspec — CocoaPods uses it only for the pod’s own targets. It must be in your Podfile (as above) and in the Xcode target.

3. Where GWIoTKit comes from

Section titled “3. Where GWIoTKit comes from”

GWIoTKit is published on CocoaPods trunk and its binary is served over HTTPS:

The version constraint comes from the plugin podspec (s.dependency 'GWIoTKit', '~> x.y'), so the host Podfile does not pin a version — it only declares the subspecs (Core and RQIAPKit; GWIoTKit’s default_subspecs is just Core). The exact zip URL changes per version; inspect it with pod spec cat GWIoTKit.

Gwell’s private spec repo (（内部仓库地址已隐去，请向对接接口人索取）) contains other Gwell pods but not GWIoTKit. If a host Podfile declares only that private source and omits trunk, pod install fails with Unable to find a specification for 'GWIoTKit'.

4. Simulator architecture

Section titled “4. Simulator architecture”

The SDK’s static frameworks have no arm64 simulator slice. On Apple Silicon you have two options:

  1. Run the simulator under Rosetta (x86_64), which the EXCLUDED_ARCHS settings above enable.
  2. Use a physical device.

Without the exclusions, a simulator build fails at link time with a missing arm64 slice.

5. Runtime requirements

Section titled “5. Runtime requirements”

  • Native pages need a usable navigation stack. Pages shown by the SDK are pushed onto the current navigation stack, so the host must satisfy two conditions:

    1. A key window has a root view controller (the Flutter container is mounted); otherwise the plugin returns error code 25100.
    2. The chain from that root view controller contains a UINavigationController; otherwise the plugin returns error code 25101.

    When either is missing the page simply never appears and the SDK reports no error. The plugin turns that into a readable error code so hosts do not mistake “page did not show up” for an SDK bug.

    The root controller generated by the Flutter template is a FlutterViewController, so it has to be wrapped in a navigation controller in AppDelegate:

    Hosts using a SceneDelegate (an UIApplicationSceneManifest in Info.plist) may still see a nil window at didFinishLaunchingWithOptions; do the same wrapping in scene(_:willConnectTo:) instead.

  • Registering for push is the host app’s responsibility; showing and routing stays with the SDK. The plugin does not request permissions or register tokens; it only relays the token you hand it. Gwell Cloud only accepts an APNs token on iOS: even a host using FCM must upload the APNs token, and the FCM token is useless to the cloud. When a push arrives or the user taps it, hand the userInfo to receivePushNotification / clickPushNotification; parsing, showing and routing are the SDK’s job.

  • macOS is not supported. The plugin declares only android and ios platforms; the GWIoT feature set requires GWIoTKit, which is not linked on macOS.

6. Troubleshooting

Section titled “6. Troubleshooting”
Symptom Cause
Unable to find a specification for 'GWIoTKit' The Podfile declares only Gwell’s private spec repo. Add CocoaPods trunk.
Link error about a missing arm64 slice for the simulator The EXCLUDED_ARCHS exclusions (from GWIoTKit and Generated.xcconfig) were removed or overridden. On Apple Silicon, run Rosetta or use a device.
The platform of the target 'Runner' (iOS 13.0) is not compatible with 'gwiot_flutter_plugin' which has a minimum requirement of iOS 15.0 The host deployment target is below 15.0.
Symbol/link errors mentioning Swift concurrency or swiftCompatibility* BUILD_LIBRARY_FOR_DISTRIBUTION = YES is missing from the host post_install.
Native page call returns 25100 No usable keyWindow.rootViewController; the call happened before the UI was ready.
Native page call returns 25101 The root controller is not embedded in a UINavigationController (the Flutter template default), so SDK pages have nowhere to push. Wrap the root controller as described in section 5.
