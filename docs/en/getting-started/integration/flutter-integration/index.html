GWIoT Flutter Demo

A complete sample of a host app built on gwiot_flutter_plugin. The plugin wraps the GWIoT iOS and Android SDKs behind a single Flutter API; this project shows how to use it: two account systems, the device list and device cards, four ways to add a device, device events, the account and settings pages, and push notifications.

Two account routes are covered, so you can follow whichever matches the account system you already have:

Account system Who owns accounts How this project demonstrates it
Gwell account Gwell Cloud (the SDK’s built-in account service) Sign-up and sign-in by phone or email, verification codes, password change
Host account Your own backend A Supabase project plays the customer cloud and performs the C2C sign-in exchange

2. Dependency source

Section titled “2. Dependency source”

pubspec.yaml already points at the right source, so a plain flutter pub get is enough:

The plugin is not published on pub.dev; it is distributed only through Gwell’s private Pub source, which allows anonymous reads, so you do not need to set PUB_HOSTED_URL. If the host is unreachable or your access has not been enabled yet, flutter pub get fails with 404 / an authentication error rather than silently resolving somewhere else — send us the error and we will sort it out.

4. Platform notes

Section titled “4. Platform notes”

Android

Section titled “Android”

The dependencies come in two layers, and missing either one gives you a successful initialize call with an SDK that never becomes ready:

  1. The plugin itself declares only com.gwell:gwiotapi (the runtime AAR). Its POM carries no dependency information at all.
  2. Your app must declare the aggregate package com.gwell:gwiotkit:1.11.07, which brings in the plugin hub, Room/SQLite and the other runtime dependencies.

Everything else the host has to configure is already in this project, one item per real failure — do not delete them:

  • All Maven repositories: maven-gwiot, maven-releases, JitPack, a jcenter mirror and mvn.zztfly.com. Without them the build fails with Could not find com.github.zhpanvip:viewpagerindicator and friends.
  • Kotlin aligned to 2.3.20, using compilerOptions.jvmTarget (Kotlin 2.3 removed kotlinOptions.jvmTarget(String)).
  • Hilt 2.57.1 plus an @HiltAndroidApp application class; kapt needs an explicit org.jetbrains.kotlin:kotlin-metadata-jvm:2.3.20.
  • buildFeatures { dataBinding = true; buildConfig = true }: without dataBinding, tapping the + button and opening the SDK’s QR scan page crashes with NoClassDefFoundError: DataBinderMapperImpl.
  • Manifest placeholders, tools:replace and jniLibs.pickFirsts, which fix manifest merging and duplicate .so failures respectively.
  • The initialization order in Application (see DemoApplication.kt): AppEnv.init → StorageManager.init → key-value import → plugin-hub init → FirebaseApp. In the wrong order the process crashes the moment sign-in succeeds, not at launch, so a startup smoke test will not catch it.
  • Firebase config: the bundled android/app/google-services.json belongs to the demo project. Replace it with the file downloaded from your own Firebase project (keep the file name).

iOS

Section titled “iOS”
  • The root view controller must be wrapped in a UINavigationController. The SDK pushes its built-in pages onto the current navigation stack; with a bare FlutterViewController the API call reports success but no page appears, and the SDK reports no error either. This project uses GWIoTNavigationController, which also decides per page whether the system navigation bar is shown.
  • Do not omit a single usage description. Accessing protected data without the matching NS*UsageDescription terminates the process instead of prompting. The project already covers camera, photo library read/write, microphone, location, Bluetooth, local network + Bonjour and background push, matching the privacy APIs the SDK actually references. When you add a page that touches a new API, scan the SDK binaries for the key name first.
  • Keep Runner.entitlements and CODE_SIGN_ENTITLEMENTS. Without aps-environment, registerForRemoteNotifications fails with Code=3000, which looks like “permission granted but no APNs token ever arrives”.
  • Firebase config: ios/Runner/GoogleService-Info.plist is the demo project’s file too; swap in your own.

5. Trying both account systems

Section titled “5. Trying both account systems”

The top-left corner of the sign-in page opens the developer settings page, where you can switch the login mode and the SDK environment and inspect SDK state and logs. The login mode is read once at initialization, so a change requires restarting the app (the page offers a restart action).

  • Gwell account: sign up and sign in directly against Gwell Cloud’s account service.
  • Host account: sign in to the host account first (this project simulates it with Supabase Auth), then the SDK asks the customer cloud for sign-in credentials over the C2C exchange. The supabase/ directory is a minimal implementation of that customer cloud (two Edge Functions plus a migration); adapt its structure to your own backend.

Once signed in, the home screen has three tabs — Devices, Events and Profile. The + button on the Devices page offers built-in QR scanning, a custom scanner, and manual product selection. The floating button in the bottom-right corner takes you back to the developer settings page at any time.

7. Troubleshooting

Section titled “7. Troubleshooting”
Symptom Likely cause
initialize succeeds but the SDK never becomes ready com.gwell:gwiotkit is missing, or a Maven repository the SDK’s transitive dependencies need is missing
Tapping + and opening the scan page crashes (Android) buildFeatures.dataBinding is off
The API returns success but an SDK page never appears (iOS) The root view controller is not wrapped in a UINavigationController; the plugin returns 25100 / 25101 to tell you which case it is
Opening the camera or photo picker crashes (iOS) The matching NS*UsageDescription is missing from Info.plist
Notification permission is granted but no token ever arrives (iOS) The aps-environment entitlement is missing (Code=3000), or you are on a simulator
The process crashes the instant sign-in succeeds (Android) The Application initialization order in section 4 was not followed
flutter pub get fails with 404 / authentication The private Pub source is unreachable or access has not been enabled
