Custom Device Settings Service

Overview

Section titled “Overview”

The SDK’s device settings page (Smart Guard) displays the complete event detection time schedule and all supported event type switches by default. When the App needs to customize the visibility of these settings (for example, hiding certain features based on device model, user permissions, or business requirements), it can implement the IHostSettingService interface to control the display.

How It Works

Section titled “How It Works”

When the SDK needs to display the [Smart Guard] related options on the device settings page, it processes in the following priority order:

  1. Check if the App has registered IHostSettingService via registerHostService()
  2. If registered, call the corresponding interface methods to get the App’s decision:
    • onDisplayEventDetectionSchedule — determines whether to show the [Guard Time Schedule]
    • onDisplayEventTriggerTypes — determines which [Alarm Event] type switches to show
  3. If not registered, the SDK uses the default behavior (show all)

Notes

Section titled “Notes”
  • IHostSettingService extends IHostService and is registered via GWIoT.registerHostService() or GWIoT.registerHostServices()
  • When onDisplayEventDetectionSchedule returns false, the SDK will hide the [Settings/Smart Guard/Guard Time Schedule] setting item
  • The supportTypes parameter received by onDisplayEventTriggerTypes is the complete list of event types that the SDK plugin currently supports and can display. The App must only return types from this list (can only reduce, not add). The SDK will display the switches in the order of the returned list
  • It is recommended to complete the service registration after the SDK initialization is complete and before the user enters the device settings page
  • If the App does not need to customize settings, it does not need to register this service — the SDK will use the default behavior (show all)
